\# Краткое руководство по Git и GitHub



\---



\## 1. Основные понятия



\* \*\*Репозиторий (Repository)\*\* — папка проекта, историю изменений которой отслеживает Git (локально или на удалённом сервере).

\* \*\*Рабочая директория (Working Directory)\*\* — файлы проекта, которые вы редактируете прямо сейчас.

\* \*\*Индекс (Staging Area)\*\* — промежуточная область, куда добавляются файлы, готовые попасть в следующий коммит.

\* \*\*Коммит (Commit)\*\* — снимок (snapshot) состояния проекта в определённый момент времени с описанием изменений и уникальным хэшем.

\* \*\*Ветка (Branch)\*\* — независимая линия разработки (по умолчанию основная ветка обычно называется `main`).

\* \*\*Удалённый репозиторий (Remote)\*\* — версия репозитория в сети (например, на GitHub, GitLab).



\---



\## 2. Первоначальная настройка Git



Перед началом работы укажите ваше имя и email (они будут привязаны ко всем вашим коммитам):



```bash

git config --global user.name "Ваше Имя"

git config --global user.email "your-email@example.com"

```



Проверить настройки:

```bash

git config --list

```

\## 3. Инициализация проекта



\### Создание нового локального репозитория

Перейдите в папку вашего проекта в терминале и выполните:

```bash

git init

```

\*Создастся скрытая папка `.git`, содержащая всю историю версий.\*



\### Исключение файлов (`.gitignore`)

Создайте в корне проекта файл `.gitignore` и перечислите в нём файлы и папки, которые не нужно отслеживать (логи, зависимости, пароли):

```text

node\_modules/

.env

\*.log

.DS\_Store

```

\## 4. Базовый рабочий процесс (Работа с коммитами)



Типичный цикл работы с изменениями:

`\[Редактирование файлов]` -> `git add` -> `\[Индекс]` -> `git commit` -> `\[История/Репозиторий]`



1\. \*\*Проверить статус изменений:\*\*

&#x20;  ```bash

&#x20;  git status

&#x20;  ```

2\. \*\*Добавить файлы в индекс:\*\*

&#x20;  ```bash

&#x20;  git add index.html       # Добавить конкретный файл

&#x20;  git add .                # Добавить все изменённые и новые файлы

&#x20;  ```

3\. \*\*Зафиксировать изменения (сделать коммит):\*\*

&#x20;  ```bash

&#x20;  git commit -m "Краткое и понятное описание изменений"

&#x20;  ```

4\. \*\*Просмотреть историю коммитов:\*\*

&#x20;  ```bash

&#x20;  git log --oneline        # Краткий список коммитов в одну строку

&#x20;  ```

\## 5. Работа с ветками



\* Создать ветку и сразу переключиться на неё:

&#x20; ```bash

&#x20; git switch -c feature/new-feature

&#x20; # (устаревший аналог: git checkout -b feature/new-feature)

&#x20; ```

\* Переключиться на существующую ветку:

&#x20; ```bash

&#x20; git switch main

&#x20; ```

\* Слить изменения из ветки `feature/new-feature` в текущую ветку:

&#x20; ```bash

&#x20; git merge feature/new-feature

&#x20; ```

\* Удалить локальную ветку:

&#x20; ```bash

&#x20; git branch -d feature/new-feature

&#x20; ```

\## 6. Регистрация на GitHub и связывание репозиториев



\### Шаг 1: Регистрация

1\. Перейдите на \[github.com](https://github.com/) и нажмите \*\*Sign up\*\*.

2\. Введите email, пароль, имя пользователя (username) и подтвердите почту.



\### Шаг 2: Настройка доступа

GitHub не принимает пароль аккаунта при отправке кода через консоль:

\* \*\*SSH-ключ (рекомендуется):\*\*

&#x20; 1. Сгенерируйте ключ: `ssh-keygen -t ed25519 -C "your-email@example.com"`.

&#x20; 2. Скопируйте публичный ключ (`cat \~/.ssh/id\_ed25519.pub`).

&#x20; 3. В GitHub: \*\*Settings\*\* → \*\*SSH and GPG keys\*\* → \*\*New SSH key\*\* и вставьте содержимое.

\* \*\*Personal Access Token (PAT):\*\*

&#x20; 1. В GitHub: \*\*Settings\*\* → \*\*Developer Settings\*\* → \*\*Personal access tokens\*\* → \*\*Tokens (classic)\*\*.

&#x20; 2. Создайте токен с правами `repo` и используйте его вместо пароля при запросе.



\### Шаг 3: Создание удалённого репозитория

1\. На GitHub нажмите \*\*"+"\*\* в правом верхнем углу → \*\*New repository\*\*.

2\. Укажите название репозитория.

3\. \*\*Не ставьте галочки\*\* на \*Initialize with README\*, \*.gitignore\* или \*license\*, если вы связываете существующий локальный проект.

4\. Нажмите \*\*Create repository\*\*.



\### Шаг 4: Отправка локального проекта на GitHub

Выполните команды в терминале внутри локального репозитория:



```bash

\# 1. Переименовать основную ветку в main (если она называется master)

git branch -M main



\# 2. Связать локальный репозиторий с удалённым

git remote add origin git@github.com:username/repository-name.git   # Для SSH

\# или: git remote add origin https://github.com/username/repository-name.git # Для HTTPS



\# 3. Отправить изменения на GitHub

git push -u origin main

```

\## 7. Сводная таблица основных команд



| Команда | Описание |

| :--- | :--- |

| `git clone <url>` | Клонировать удалённый репозиторий на свой компьютер |

| `git status` | Показать состояние файлов (неотслеживаемые, изменённые, в индексе) |

| `git diff` | Показать построчные изменения, ещё не добавленные в индекс |

| `git add <file>` | Добавить файл в область подготовки (индекс) |

| `git commit -m "msg"` | Сохранить изменения в репозиторий |

| `git pull` | Получить свежие изменения с сервера и слить их с текущей веткой |

| `git push` | Отправить локальные коммиты на удалённый сервер |

| `git branch` | Список существующих локальных веток |

| `git reset --soft HEAD\~1` | Отменить последний коммит, оставив изменения в файлах |
